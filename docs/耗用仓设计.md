# 耗用仓设计

本仓把库存余额、项目实际耗用和核销交接建在同一份物料事实上。全部口径是合成的内部约定（见 docs/资料口径.md），不计算真实税款、不向监管系统申报。实现不引入新依赖，只用标准库。

## 分层

```
data/ 原始资料（契约见 data/catalog.json）
  │  receive / receive-dir：落地区保留原文件与接收历史，相同摘要不增加事实，
  │  同记录键的新文件是整行修订，接收次序由调用方的 --at 明确
  ▼
warehouse/landing/  接收历史 receive_log.jsonl + 原样保存的文件
  │  build_facts：在统一知识截点上合并修订、换算、核对
  ▼
事实层（consume/facts.py）
  │  build_marts：同源派生三张仓表
  ▼
warehouse/mart/  可读仓表 CSV + recon.json + build_meta.json
  │  handover：按核销期出交接，确认后版本可回看，修订另行比较
  ▼
warehouse/handover/<期间>/vN.json + vN.md + index.json
```

## 关键口径的实现位置

- **知识截点**：每次构建只有一个截点（`--cutoff`），库存、成本、核销三张表同源，不会出现库存已用新规格而成本仍用旧规格。文件知识时刻是接收时记录的 `--at`；密度补正另有行内 `received_at`，两者都晚于截点才不可知。历史截点不会用到较晚才知的值。
- **双计量**：计数与质量分别守恒。计数只认根包装实收瓶数，分装子管是空包装另列，销毁未确证不减瓶数；质量按容器台账逐笔出账。ml→g 只在物质、日期、温度均适用时换算（consume/facts.py 的 `to_grams`），无适用密度即未知，不插值、不借用别的物质。
- **规格按封装日适用**：P1 封装于 2026-09-20，适用旧规格 SP1（100 g），不用当前 SP2 解释旧包装。实收净克是付款事实，后续补正不改变它。
- **实物流转语义**：issue/return/transfer 只变保管方（在手余额随保管方移动，全区总量不变）；use/evaporate/destroy 才是实物出账；分装是父管到子管的移动，不创造新入区量。子管在分装时刻继承父管保管方与单位成本（分装与转移按业务时点交错处理）。
- **pending 不双计**：申报未确证的量单列 `pending_out_g`，既不进确认损耗也不进可用余量；`expected = book − pending` 只是"若申报物理成立，称量应对上的量"，实测对上也不自动证明其类别可核销。
- **称量是独立核对**：容差 0.2 g，超差待核，不自动生成损耗配平。补正后 P1A 账面 19.4 g、实测 19.2 g，差 −0.2 g 在容差内，仍为 ok。
- **成本**：按实际耗用归属项目，成本期是实际消耗月份（U3 实际 10 月消耗、核销期 2026-11，成本期仍是 2026-10）；单价取物质取得价每克；未知质量不伪造成本，该行挂待核。账单舍入到分，尾差归分摊基数最大项，并列按业务键升序。
- **核销确认资格**：仅 confirmed use、documented evaporate、witnessed destroy；pending 不自动核销；研究失败不自动等于销毁。质量未知的确认行仍不能确认金额。
- **交接**：每期交接包含确认行、待核去向、未决质量差额和未决事项，不为月末总数删除待核。内容哈希相同不新增版本；确认只翻转标记，不改已存内容；后来的修订产生新版本，用 diff 另行比较。
- **差异分类**：每个派生行记录来源依赖（deps），版本间输入差集与行依赖求交，把变化分成新增实物动作（packs/decants/movements/uses/weighings）、历史资料补正（density_corrections/specifications）、成本资料变化（materials），并汇总到项目与期间。

## 待核队列

待核项有编号、主题、原因、所需资料和影响范围，来自：分装规格不明、消耗质量未知、处置申报未确证、容器余量未知、称量超差、保管方矛盾、超耗、规格缺失、引用缺失。补资料（如 M2 的适用密度）以新文件接收后，相应待核自动消解并改变可折算量与项目分摊，但已领出瓶数与实收事实不变。

## 三方核对

`check` 输出并校验：按物质的质量守恒（实收 = 确认出账 + 待核 + 实测 + 容差内余差，未知环节单列不掩盖）、计数守恒（实收瓶数 = 现存 + 已销毁，空包装另列）、成本↔核销按去向行同源（同一 use_id 的成本期与核销期可不同，金额一致）。查库存、成本或核销中的任何一项，都能沿 use_id / pack_id 核对另外两项的数量依据。
